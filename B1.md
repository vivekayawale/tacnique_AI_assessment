# B1 — The Glacier cost gotcha

What's the actual cost impact of an early deletion after archival? How would you redesign the
lifecycle so this stops quietly costing more than budgeted?

`GLACIER` (S3 Glacier Flexible Retrieval) has a 90-day minimum storage duration. The object
was in that class for only 10 days, so deleting it on day 40 incurs an early-deletion charge
for the remaining 80 days of the minimum period. The object is deleted immediately, but the
storage charge does not stop immediately; this is a prorated charge, not a requirement to
restore the object first.

Do not transition photos that may still be subject to prompt deletion into a class with a
minimum storage duration. Keep deletion-eligible objects in S3 Standard, and archive only
objects whose retention policy guarantees they will remain stored for at least 90 days after
the transition. Model that eligibility explicitly (for example, with separate prefixes or
tags and lifecycle filters), and set the transition timing from the date that guarantee
begins—not merely from upload. If deletion can be requested at any time, there is no safe
transition date for those objects; keep them in a class without this minimum-duration penalty.
Track storage-class costs and configure budget alerts so the residual charges are visible.
