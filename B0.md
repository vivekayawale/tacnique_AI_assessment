# B0 — The `count` trap

What does `terraform plan` show when a middle landlord account is removed from the list? Why is
that dangerous here? What's the fix?

With `count`, Terraform identifies each bucket by its numeric list index, not by landlord
account ID. Removing an account from the middle shifts the later entries to different indices,
so Terraform can plan to replace buckets or destroy an index that no longer exists. For S3,
destroying a bucket risks deleting its contents; replacing a bucket can also fail because the
old bucket name is already in use.

Use `for_each` with landlord account IDs as stable keys (for example,
`for_each = toset(var.landlord_accounts)` and `each.key`). Existing count-based state must also
be migrated to the new keyed addresses, such as with `moved` blocks, so Terraform recognizes
the already-provisioned buckets instead of treating them as new resources. Removing an account
from the configuration will still plan to destroy that account's bucket, so keep its ID in the
input until the bucket is intentionally decommissioned.
